# 2.0 holding list

Status: current

Part of the roadmap: [ROADMAP.md](../ROADMAP.md). Path shorthand (`E:`, `C:`, `P:`, vault) is defined there.

The rule (owner, 2026-11-18): anything that does not break the contract is 1.x (called v1+ before 2026-11-22);
anything that breaks it is 2.0 (called v2). The contract and the four tests that decide are in
[post-1.0-plan.md](post-1.0-plan.md) and the engine's `docs/compatibility-contract.md`.

2.0 is not a feature release. It is the list of breaking changes waiting for a reason to break. Nothing
is scheduled for 2.0 today.

## Accepted breaks waiting for 2.0

A change that breaks the contract and was not done before the 1.0 freeze.

None yet. An item moves here when the owner decides not to do it before the freeze, with a line in
[decisions.md](decisions.md).

## Not frozen in 1.x

Surfaces labelled experimental may change in a 1.x minor, so a change to them is not 2.0: the Python
API (`decoy.mask`, `decoy.scan`) and custom providers with the connector SDK. The `decoy library`
commands are decided at the release gate. Row EXPERIMENTAL-TIER in [groups/release.md](groups/release.md).

## Fixed for the life of 1.x

These cannot change in any 1.x release. They are listed so nobody plans a 1.x feature that needs one.

| Surface | What is fixed | Source |
|---|---|---|
| Determinism | The derivation path (HKDF `derive`, FPE keying, Faker seeding, `SEED_PROTOCOL_VERSION`). Same input, seed and config give the same bytes. | contract 3.3 |
| Faker data | The Faker release the launch engine pins. Faker's name and data pools are not semver-stable, so a Faker upgrade changes deterministic output. A 1.x Faker upgrade is possible only if Decoy first ships its own copy of the pools it uses (candidate Faker pool snapshot; see FAKER-MIGRATE). | `E:pyproject.toml` |
| Vault | The vault format and its readers are permanent. | contract 3.2 |
| Stored formats | A tagged format is never changed in place; a new tag is added and the old reader stays. | contract 4.2 |
| `when:` reserved names | Adding a reserved name refuses configs that use it as a column name. | contract section 1 |
| Reason registry | Append-only. A reason may stop firing; it is never renamed or removed. | post-1.0 plan |
