## 2. Established solutions

- **Static version manifest plus signed metadata.** TUF's timestamp role (signed, short expiry, monotonic version)
  is what `version_document.py` already follows (its docstring cites the TUF specification). TUF keeps the
  timestamp fresh with a scheduled re-sign (Q4).
- **Install script on the vendor domain, binaries from release storage.** `rustup`, `uv` and `deno` serve
  `install.sh` from their own domain and fetch binaries from GitHub Releases or object storage.
- **One schema plus a shared conformance suite.** JSON Schema publishes a language-neutral test suite
  (`JSON-Schema-Test-Suite`) that every validator runs; TUF ships conformance tests that each client
  implementation runs. Here the CLI owns the schema and the cases, and every reader runs the same cases. The CLI
  already keeps versioned schemas in `docs/schemas/` (`decoy-error-v1.schema.json`, `decoy-ci-v1.schema.json`) and
  validates them with `jsonschema` in tests (`pyproject.toml:175-178`, test-only).
- **Vendored copy with a recorded digest.** decoy-web already vendors a CLI reference
  (`docs-src/scripts/sync-cli-reference.mjs`); this plan uses the same sync shape, plus a recorded SHA-256 that the
  check compares.
- **Static-site build checks.** The site fails its build on bad claims and links (`npm run check`); new checks join
  that command.

## 3. Design notes

1. **Small files on the website, bundles at `ARTIFACT_BASE`.** Pages serves `version.json`, `.sig`, `.sshsig`,
   `install.sh`, `install.ps1` and `release-key.pub` under `/cli/`. Bundles and their sidecars live at
   `release_identity.artifact_url(version, name)`, which is `f"{ARTIFACT_BASE}/v{version}/{name}"` (CLI-REL note 16).
   The value of `ARTIFACT_BASE` is CLI-REL OQ-4's answer; under its recommendation it is the `v<ver>` GitHub
   Release of `decoy-data/decoy`. This plan holds no copy of it.
2. **The document lives in decoy-web git.** CLI-REL S0b's `publish`, `resign` and `rollback` modes open a
   decoy-web PR that adds `src/cli/version.json` and its sidecars. Git history is the publish log, the new
   `check.yml` runs `npm run check` before merge, and a merge deploys. The PR commit is made through CLI-REL's one
   choke point `_rel_web.commit_and_push`, which sets author and committer `ckeep <decoy@trydecoy.com>` and reads
   them back (CLI-REL note 15).
3. **One version-document contract, owned by the CLI.** RW-C3 adds two generated files under `docs/schemas/`
   (CODEMAP row "Versioned schema artifacts"):
   - `cli-version-document-v1.schema.json`: JSON Schema 2020-12 for the payload (required fields, types,
     `schema_version` const, `serial` integer minimum 1, `expires` and `generated` patterns, the artifact entry
     shape, the target names from `src/decoy/distribution/targets.py:28-32`), plus one `x-decoy-release` member:
     `site_origin`, `default_url`, `artifact_base`, `artifact_host_exception`, `artifact_url_template`
     (`{artifact_base}/v{version}/decoy-{version}-{target}.tar.gz`), `sig_suffix` (`.sig`), `cli_repo`, `web_repo`.
     `$id` is `https://trydecoy.com/schemas/cli-version-document-v1.schema.json`.
   - `cli-version-document-v1.cases.json`: the conformance cases. Each case is the exact document bytes
     (base64), a signature by a fixed-seed throwaway Ed25519 key (Ed25519 is deterministic, so the file is
     byte-stable), and the expected verdict per reader (`python`, `install_sh`, `install_ps1`, `web`): `accept` or
     one refusal code.
   Both are written only by `packaging_tools/version_contract.py --write`, which reads `version_document`,
   `release_identity` and `targets`; a sentry fails when the committed bytes differ from a fresh run (the
   `regen-diagrams` pattern). The Python reader is not rewritten to read the schema; the cases prove it agrees.
4. **Every reader runs the same cases.** On the CLI, AT-C12 runs every case through `parse_document` plus
   `check_fresh` plus signature verify, through `install.sh`'s document stage against a loopback server, and
   through `install.ps1` under `pwsh` (Windows cell, or Linux when `pwsh` is present). decoy-web vendors both files
   and runs every case through `check-dist.mjs`'s document stage (AT-H7). A reader that disagrees with its expected
   verdict fails its own repo's check. Agreed codes for the shared core: signature invalid, wrong
   `schema_version`, `serial` missing, zero, a string or a boolean, `expires` missing, malformed or past. The web
   reader also refuses artifact URLs that are not exactly the template.
5. **`install.ps1` gains the same checks.** The cases show it accepts an expired, wrong-schema or zero-serial
   document today. RW-C3 adds the schema, `serial` and `expires` checks and the trust-state replay check that
   `install.sh:287-292` already has, in the same order. Windows stays gated by WIN-FEAS (row 89); the code still
   must not lag the contract.
6. **The web check holds no contract literal.** `scripts/lib/contract.mjs` loads the vendored schema and exposes
   `fieldRule(name)` (the `type`, `const`, `minimum`, `pattern` of one property) and the `x-decoy-release` values.
   `check-dist.mjs` verifies the signature first, then reads only the fields its rules use (`schema_version`,
   `serial`, `expires`, `latest`, `artifacts`) through `fieldRule`. It never lists fields, types or hosts itself;
   it is not a second validator of the full shape, because a document that passes the signature against the
   pinned key was written by the CLI writer, which AT-C11 checks against the schema.
7. **Digest guard on the vendored copy.** `scripts/sync-contract.mjs --from <CLI checkout> --ref <sha>` copies the
   two files byte for byte to `scripts/contract/` and writes `scripts/contract/source.json`
   `{cli_commit, files: {name: sha256}}`. `check-dist.mjs` refuses `dist_contract_digest` when a vendored file's
   SHA-256 differs from `source.json`, and `dist_contract_version` when the schema `$id` is not the one it
   implements. A host change (OQ-4) is then: CLI regenerates, decoy-web re-syncs in its own PR, then the publish PR.
8. **The serial rule compares against earlier versions only.** The checked artifact is the working-tree
   `src/cli/version.json`. If its bytes equal the blob at `HEAD^1` (a page-only commit), the rule passes without a
   compare. Otherwise the history is `git log --first-parent --format=%H HEAD^1 -- src/cli/version.json`, which
   starts at the first parent and so never contains the checked commit; the checked `serial` must exceed the
   maximum `serial` of those blobs. No earlier blob (first publish) passes. On a normal push to main, `HEAD^1` is
   the previous main commit; on a PR merge ref (`refs/pull/N/merge`) it is the main tip, so a branch that raises 3
   to 4 while main holds 5 fails, and a branch that raises main's 5 to 6 passes. A shallow repository
   (`git rev-parse --is-shallow-repository` is `true`) is `dist_history_missing`, never a pass.
9. **The download page reads the signed document and the contract.** `src/_data/cliRelease.js` parses
   `src/cli/version.json` at build and takes the bundle host for the page copy from the contract's
   `artifact_base`. The install host is `site.json` `url`, and AT-D3 checks it equals the contract's
   `site_origin`, so the website and the CLI share one value.
10. **`/proof` reuses the docs app.** `docs-src/lib/proof.ts` validates the manifest with zod; the page composes
    the existing components and `build-docs.sh` copies the export to `dist/proof/index.html`.
11. **A placement map for decoy-web.** RW-H adds a root `CODEMAP.md` with a "Where things go" table (section 11)
    and points `README.md` "Structure" at it. `docs-src/CODEMAP.md` gets a first line saying it covers only the
    docs app; rewriting it is a follow-up.
12. **No browser in CI unless the owner wants one (OQ-W1).** The download page is static Eleventy output with no
    client framework (`README.md:3-5`); `src/js/site.js` makes no request and only writes the theme to
    `localStorage` (`site.js:11`). A static scan of the page and every script and stylesheet it loads proves P7
    without Playwright.

## 4. Release sequence (release-and-rollback)

Row 91 builds the place; row 94 publishes into it through CLI-REL. The order inside row 94's publish (CLI-REL
section 4, R4 to R6):

1. CLI-REL uploads bundles and sidecars to `ARTIFACT_BASE`, reads each back and confirms the public URL.
2. CLI-REL opens the decoy-web PR with the signed files, committed by `ckeep <decoy@trydecoy.com>`. `check.yml`
   runs `npm run check`, which runs `check-dist.mjs` (5.1). Merge; `deploy.yml` reruns the check and Pages deploys.
3. Wait until `https://trydecoy.com/cli/version.json` serves the new `serial` (Pages caches for about 10
   minutes), then run row 94's smoke from the published artifact.
4. Flip `prelaunch` to `false` in `site.json` in a separate decoy-web commit after the smoke is green.

Before step 1, if the contract changed (for example an OQ-4 answer moved `ARTIFACT_BASE`), a decoy-web PR re-syncs
`scripts/contract/` first; otherwise the publish PR fails `dist_artifact_url`, which is the intended order.

Rollback: never `git revert` `src/cli/version.json`. CLI-REL's `rollback` mode publishes a new document with a
higher `serial` whose `latest` is the previous version. `check-dist.mjs` refuses a lower or equal serial, so a
revert fails the build (AT-H4). A bad page edit alone is a normal revert.

Re-sign (Q4 answered): CLI-REL's `resign` mode runs weekly and re-signs when fewer than 17 days remain, so a
document has about 16 days left when replaced; the scheduled warning at 10 days fires only when a re-sign was
missed, and the deploy check (expired or under 3 days) never blocks a routine page fix.

3. `version.json.sig` verifies over the exact bytes of `version.json` with `release-key.pub`, using Node's built-in

5. Serial rule as in note 8.
6. For every target in `artifacts`, `url` equals the contract's `artifact_url_template` filled with `latest` and the
   target, and `sig` equals `url + sig_suffix`. Exact string equality, no prefix match.
7. The PEM block inside `install.sh` and the key in `install.ps1` equal `release-key.pub`.
8. Static request scan of `dist/cli/index.html`: every `src`, `href`, `srcset`, `action`, CSS `url()` and

   analytics snippet; no `document.cookie`, `fetch(`, `XMLHttpRequest`, `sendBeacon`, `WebSocket` or `new Image` in

9. Identity: no tracked text file (`git ls-files`) contains `louiskeep` (case-insensitive); `package.json`
   `repository.url` names the contract's `web_repo`; `site.json` `github` names its `cli_repo`.

Before row 94 publishes, `src/cli/` holds only `release-key.pub` (once G2 commits it). The check passes when

`src/_headers` and `src/_redirects` are deleted with the passthrough entries that copy them, since Pages ignores

   the signed document.

8. **Pages cache served the old document during the smoke.** Step 3 in section 4 polls for the new `serial`.
9. **Someone added a script to the download page that builds a URL at run time.** The static scan refuses request
