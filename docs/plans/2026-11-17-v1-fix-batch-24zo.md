## 3. Rows

### 3.1 24zr: dropped, not a defect

Facts at base (`C:src/decoy/cli/setup/__init__.py`): without `--yes`, `decoy setup` refuses to run off a terminal: `if not yes and not sys.stdin.isatty(): emit_error("setup needs a terminal; pass --yes to accept."); raise typer.Exit(EXIT_USAGE)`. The reason is that the settings sections still prompt: `SECTIONS` holds `ResourcesSection` (`C:src/decoy/cli/setup/_sections.py`), whose `ask` prompts for max memory and threads (`C:src/decoy/cli/setup/_resources.py:43`). `--ner skip` answers only the models step (`_models.py` returns `{"ner": "skipped"}`). So the command does need input that `--ner skip` does not give, and the refusal with a clear hint is correct.

Recommendation to the owner: close the row. If the wording is the concern, a one-line message change ("setup asks for memory and threads; pass --yes to accept the proposed values") can ride any later CLI slice. Not planned here.

### 3.2 24zt: dropped, belongs to F16 C2

### 3.3 24zv: fidelity warning lines print key names

Facts at base:

- `C:src/decoy/ui/summary.py:162` `report_warning_records` handles `null_drift` and `kind_drift`. Every other code takes the `else` branch (line 189): `keys = ", ".join(sorted(str(k) for k in detail)); text = f"{code_} ({keys})"`. That prints `gof_unavailable (column, metric, reason)`: the key names, which read like unfilled placeholders.
- `C:src/decoy/ui/summary.py:67` `_generic_message` already prints `key=value`, with a dict or list shown as `<n entries>` (`_fact`). It is the card's existing fallback for other warning streams. It prints every scalar with `str(value)`, so it is value-free only as long as the producer's detail holds no cell values. On this path that holds today (next point).
- Engine `E:src/decoy_engine/quality/report.py:308` emits `gof_unavailable` with detail `{column, metric, reason}`. `metric` is a metric id (`ks_complement`, `chi_cramers_v`); `reason` is a code from `E:src/decoy_engine/quality/_distribution_gof.py` (`missing_histogram`, `malformed_histogram`, `zero_mass`, `insufficient_identifiable_support`). The other codes on this path (`E:src/decoy_engine/quality/report.py:277`, `:285`, `:296`) are `column_survival` (lists of column names), `row_count` (counts), `no_comparable_columns` and `no_comparable_joints` (empty detail). None carries a cell value.
- Caller: `render_warnings(state, report_warning_records(...))` at `C:src/decoy/ui/summary.py:454`.

V1 behavior:

1. A `gof_unavailable` branch: `column <column>: <metric> not computed (<reason>)`, with `column=` set on the record.
2. The `else` branch calls `_generic_message(code_, None, detail.get("column"), detail)`, so there is one fallback and it prints facts, not key names. A list (for example `missing_columns`) prints as `<n entries>`, as elsewhere on the card.
3. `--json` output is unchanged.

Failure modes:

| Case | Behavior |
|---|---|
| `gof_unavailable` with all three keys | `column age: ks_complement not computed (missing_histogram)` |
| `gof_unavailable` with a missing key | the missing part prints `n/a`, never the key name |
| `row_count` | `row_count: expect_parity=True, source_rows=100, output_rows=90` |
| `column_survival` | `column_survival: missing_columns=<1 entries>, added_columns=<0 entries>` |
| empty detail (`no_comparable_columns`) | the code alone (today's) |
| detail not a dict | treated as empty (today's) |
