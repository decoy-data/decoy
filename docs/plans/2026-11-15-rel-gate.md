## 1. FRAME

### Problem

Row 93 is the last gate before the CLI V1 release (row 94). Its parts exist only as prose today:

- The surfaces that freeze at 1.0.0 are pinned unevenly. Exit codes are pinned well
  (`tests/unit/test_exit_codes.py:25`, `tests/unit/test_exit_code_registries.py:25`). The engine run
  result round-trips a fixture corpus but has no committed schema file. The YAML pipeline schema
  (`PipelineConfig`, engine `config/_pipeline.py:87`) has no snapshot at all; the only guard is a PR-body
  checklist (`scripts/check_compat_preflight.py`), and its `FROZEN_PREFIXES` leave out
  `src/decoy_engine/run_result/` and `src/decoy_engine/reasons/`. No per-command snapshot exists for a
  successful `--json` document.
- The CLI version literal `0.1.0` (`src/decoy/_version.py`) is not tested against `pyproject.toml`; only
  the SBOM test reads the pyproject version (`tests/unit/test_sbom_script.py:604`).
- The engine repin checklist (`docs/ROADMAP.md:197-199`) is prose and names `PIN_PREFIX` and a
  Dockerfile `ARG`, neither of which exists on CLI main. The pin lives in five places: `pyproject.toml:136`,
  `requirements-dev.lock:380`, `scripts/dev/lock_version.sh:17`, `.github/workflows/ci.yml:295`,
  `.github/workflows/release-smoke.yml:84`.
- `docs/release/smoke-log.md` still reads "_no green runs yet_", although `release-smoke.yml` ran green
  eight times between 2026-09-28 and 2026-11-09 (`gh run list`). The runs were never recorded, and they
  smoke a wheel, while `docs/install.md` says V1 ships a signed per-platform bundle. No workflow calls
  `packaging_tools/smoke_install.py`, the bundle smoke.
- There is no CLI `release-readiness.md` template or instance.
- License and install wording disagree. `docs/release/versioning.md:39-44` gates 1.0.0 on "OSS.7 publish
  pipeline + first real-PyPI green push"; `docs/install.md` says the install path is a signed bundle and
  public `pip install` comes later; engine `README.md:18` still says `pip install decoy-engine`.
  `LICENSING.md:11` names a placeholder licensor and `LICENSING.md:73` carries `TODO(licensor)`.
- Row 93's own text says the engine is Apache-2.0; engine #553 (`051b84cb`) relicensed it to FSL-1.1-ALv2.
  The row text is stale (follow-up FU-4; this plan does not edit `ROADMAP.md`).

### Guarantee (what REL-GATE promises)

1. **One frozen-surface map.** Every surface `docs/release/versioning.md` and engine compatibility contract
   section 3 call public is listed once in `docs/release/frozen-surfaces.md`, with the test that pins it.
   A listed test that does not exist, or a public surface with no row, turns a sentry red.
2. **Snapshots for the unpinned surfaces.** The YAML pipeline schema, the run-result schema and every
   successful `--json` document shape each have a committed, value-free snapshot that a test compares
   byte for byte. Any change shows up as a snapshot diff in review.
3. **One launch pin.** A single check (`scripts/release/launch_pin_check.py`) proves that every place
   the CLI names an engine version names the D-4 tag, that the CLI version agrees in `pyproject.toml`,
   `decoy.__version__` and `decoy --version`, and that the tag's reason-registry pin is release-ready.
4. **A recorded canonical smoke.** The canonical R1 smoke installs the signed release-candidate bundle on
   each supported platform, runs `decoy doctor`, a real mask run on the bundled `minimal` template and the
   native-route assertion, and appends one row per green run to `docs/release/smoke-log.md` with the
   bundle manifest digest, CLI SHA, engine tag and run URL or host.
5. **A filled readiness instance.** A template lists every gate with its command, evidence and owner. The
   instance for 1.0.0 is a dated record; a checker refuses an instance with a missing row, an empty result
   or no owner sign-off. A release tag without a complete instance is a draft, not a release.
6. **A wording checkpoint.** One license string (FSL-1.1-ALv2) and one install story (signed bundle;
   public `pip install` later) across the CLI and engine docs, pinned by tests. At readiness time the
   checker refuses the licensor placeholder and the `TODO(licensor)` marker until counsel answers.

### Non-goals

- Publishing anything, signing anything, creating the signing key or the `native-release` Environment
  (rows 90 and 94; owner tasks).
- Deciding the licensor entity or a contributor license agreement (owner and counsel; Q1, Q2).
- Post-launch compatibility diffs against the 1.0.0 tag (`griffe check`, schema diff). They matter from the
  first monthly release, not for 1.0.0 (FU-1; Q6).
- The website download page and docs flip (rows 91, 92), the container image (row 90a), Windows
  feasibility (row 89), the QA checklists (row 92a). REL-GATE reads their results; it does not build them.
- Changing any frozen behaviour. The slices add checks and docs. The one behaviour change, the engine
  pre-GA to GA flip, is its own slice gated on Q3.

### Failure modes

- A frozen surface changes after the freeze and nobody notices (silent contract drift).
- The CLI ships pinned to an engine other than the one QA tested (pin skew between five files).
- The smoke runs green on an artifact that is not the one released (wheel instead of bundle, or a bundle
  built from another commit).
- A readiness instance is "filled" with blank or copied rows.
- The release ships with a placeholder licensor or contradicting install instructions.
- A snapshot regenerates silently in a dependency bump (for example a pydantic upgrade reshapes
  `model_json_schema()`) and the reviewer accepts it as noise.

## 2. Established solutions

Searched first (2026-11-15), then read against the repos:

- **Public Python API breakage:** Griffe's `griffe check <pkg> --against <tag>` compares a package's API
  with a git ref and exits 1 on a breaking change; NVIDIA Megatron Core runs it in CI. Fits the engine's
  46-parameter `run_pipeline` and root exports after 1.0.0 (FU-1). Nothing to compare against for the first
  release, so it is not in the 1.0.0 gate.
- **Schema compatibility:** Buf's breaking-change detection and Confluent Schema Registry compatibility
  modes are the established pattern for wire schemas (backward, forward, full). For JSON Schema the tools
  are young (`jsoncompat` for Draft 2020-12, `json-schema-diff`, `api-schema-diff`). For 1.0.0 we take the
  simplest established form: a committed generated schema with a byte-equality test, the pattern the CLI
  already uses for `docs/schemas/decoy-ci-v1.schema.json`
  (`tests/unit/test_ci_manifest.py::test_generated_schema_matches_the_committed_schema_byte_for_byte`).
- **CLI stability contracts:** projects reaching 1.0 pin the exit-code table, the command and flag set and
  the machine-readable output in tests, and check them against the docs (for example a Codeberg PR "test:
  pin the 1.0 stability contracts"). Golden tests run on `--json`, never on human text. The CLI already
  pins the command and flag set (`tests/unit/test_cli_surface.py` re-renders `docs/cli-reference.md`) and the
  exit codes; this plan adds the `--json` shapes.
- **Release readiness:** a production-readiness checklist with named commands, evidence per row and a
  sign-off (Google SRE PRR; the platform's archived `v1-release-readiness.md`: "A release tag without all
  commands green + all manual gates marked is not a release; it is a draft"). We reuse its structure.
- **Release smoke from the shipped artifact:** install the exact signed artifact on a clean host and run a
  real command (packaging spec build step 5; `packaging_tools/smoke_install.py` already does this over a
  local HTTP server with a throwaway key).

## 3. Design notes

1. **The map is the choke point for "what is frozen".** `docs/release/frozen-surfaces.md` is a table: surface,
   owning repo, owning module, pinning test, snapshot file. The sentry parses it (the same pattern as
   `tests/sentry/layout/test_codemap_paths.py`) and checks each path exists. A second check lists the public
   surfaces from code (exit-code constants in `exit_codes.__all__`, every leaf command with `--json` from the
   walk in `tests/e2e/first_user/test_items_error_envelope.py`, every file in `docs/schemas/`) and refuses a
   surface that has no row. Mutation: delete a row, or point one at a missing test.
2. **Snapshots are value-free by construction.** A `--json` shape snapshot records key paths and JSON types
   (`object`, `array`, `string`, `integer`, `number`, `boolean`, `null`), never a value. Arrays record the
   union of their element shapes. Inputs are the synthetic files the first-user tests already build
   (`tests/fixtures/qa_first_user/`, copied to `tmp_path`). A shape cannot hold a row value, a path or a
   secret because the writer emits only type names.
3. **Schemas are generated, then committed.** The engine writes `PipelineConfig.model_json_schema()` and the
   `RunResult` serialization schema to `tests/snapshots/frozen_schemas/` with one script; a test regenerates
   in memory and compares bytes. The pydantic pin in the certified lock keeps generation stable; a pydantic
   bump that reshapes the output turns the test red, and the diff is reviewed as a contract change (pre-mortem
   P3).
4. **One launch pin check instead of a prose checklist.** `scripts/release/launch_pin_check.py` reads the
   five pin sites by fixed pattern and fails on any mismatch or any site it cannot parse (a site it cannot
   read is a failure, not a skip). The prose checklist at `docs/ROADMAP.md:197-199` then points at the
   script (FU-3, done by the orchestrator).
5. **The readiness checker validates structure, not truth.** It checks that the instance has every template
   row, each result is one of `pass`, `fail`, `accepted-known-limit`, each `pass` row cites an evidence
   link (run URL, record path or SHA), `accepted-known-limit` rows name the V2-LOG entry, and the sign-off
   block names the owner and a date. Truth comes from the commands each row names.
6. **The smoke records itself.** `scripts/release/record_smoke.py` appends a row built from the smoke's own
   JSON summary, so a human never types a SHA. It refuses to append a red run and refuses an edit to an
   existing row (append-only, as the log's header already states).

### 5.2 Snapshots (slices RG-F1 engine, RG-F2 CLI)

- Engine `scripts/release/frozen_schemas.py --write` writes the two schema files with sorted keys, two-space
  indent and a trailing newline, through the canonical JSON foundation (`src/decoy_engine/_canonical/`).
  `--check` compares and exits 1 on a difference, printing only the file name and the first differing JSON
  pointer, never schema text beyond that pointer.
- Engine `tests/snapshots/test_frozen_schemas.py` runs the same comparison in the suite.
- Engine `scripts/check_compat_preflight.py` gains `src/decoy_engine/run_result/`,
  `src/decoy_engine/reasons/` and `tests/snapshots/frozen_schemas/` in `FROZEN_PREFIXES`, so a PR that
  touches them must carry the section-9 checklist.
- CLI `tests/e2e/release_freeze/test_json_shapes.py` runs each `--json` leaf command once on its synthetic
  good input (the existing `BAD_INPUT` table's good-file twin; commands listed in `EXEMPT` there need a
  good-input entry or a stated exemption here too), reduces stdout to a shape and compares it with
  `tests/fixtures/release_freeze/json-shapes.json`. An environment variable is not a regeneration switch:
  regeneration is `python -m tests.e2e.release_freeze.write_shapes`, run by a person and reviewed.
- The engine golden `.sha256` files with no reader (`mask_faker_seeded`, `mask_hash_only`, `mask_redact`
  under `tests/snapshots/golden/`) are traced to their producer in RG-F1. The slice wires a reader if the
  producer still exists, or lists them in FU-2. It deletes no test file.

### 5.3 Launch pin check (slice RG-F3)

`scripts/release/launch_pin_check.py --engine-tag vX.Y.Z [--engine-repo PATH]`:

1. Reads the five CLI pin sites by fixed regular expressions (`fullmatch` per line) and requires each to
   name the tag (or its commit for `requirements-dev.lock`). A missing or unparsable site exits 1 with the
   file name and the reason code `pin_site_unreadable`; a mismatch exits 1 with `pin_site_mismatch`, the file
   and both version strings (versions are not data values).
2. Requires `pyproject.toml` `version`, `src/decoy/_version.py` `__version__` and the output of
   `python -m decoy --version` to agree.
3. With `--engine-repo`, runs the engine's `scripts/release/reason_release_pin.py --check --release-ready` at
   the tag commit in that checkout, read-only.
4. Exit 0 pass, 1 failure, 2 usage error. Output is one line per site, no file contents.

### 5.4 Canonical smoke (slice RG-S)

- `packaging_tools/smoke_install.py` gains a candidate mode: `--from-dist DIR --pubkey PEM --version V`. It
  serves the given signed bundle set over the existing loopback-only server instead of building one with a
  throwaway key, installs with `install/install.sh` (or `install.ps1` on Windows), then runs `decoy --version`,
  `decoy doctor --json`, `decoy run` on the bundled `minimal` template with a throwaway mask secret created
  in the temp directory (file mode 0600, never printed), and asserts the native route engaged (packaging spec
  step 5). It prints one JSON summary: platform tag, CLI version, engine version, bundle manifest SHA-256,
  per-step pass or fail, wall time. No source rows, no secret, no absolute home path.
- `scripts/release/record_smoke.py SUMMARY.json --run URL_OR_HOST` appends one row to `smoke-log.md`.
  It refuses a summary with any failed step, a version that is not the candidate's, or a manifest digest
  that differs from the candidate's `SHA256SUMS`.
- Platforms: Linux x86_64 and aarch64 (VMs or GitHub-hosted runners), macOS arm64 (the Mac mini, as
  `camkeep`, own folders only), Windows x86_64 only if row 89 clears it (Q5). macOS Intel is unsupported
  (owner 2026-11-12) and is not smoked.
- The existing wheel smoke (`release-smoke.yml`) stays as the weekly regression lane. Its past green runs
  are recorded once in a separate "Wheel smoke (not the release artifact)" table in the same log, so the
  G3 gap reads honestly; they do not count toward R1.

## 14. Pre-mortem

- **P1 The freeze happens on a moving main.** A V1 fix merges after G3 and nobody reruns the snapshots. Guard:
  the readiness instance records the CLI SHA and engine tag at G3 and at G7; `readiness_check.py --release`
  requires them equal or a rerun row for the later SHA.
- **P2 Snapshot fatigue.** Reviewers wave through regenerated snapshots. Guard: the engine preflight prefix
  forces the section-9 checklist; CLI snapshot changes need a CHANGELOG line (G3 decision point).
- **P3 Pydantic or Typer upgrade reshapes generated output.** The schema or reference text moves with no
  contract change. Guard: the certified lock pins both; a bump is reviewed as a contract change and the diff
  read, never regenerated blind.
- **P4 The shape test is flaky.** Commands that print timings or paths change types between runs (a `null`
  duration). Guard: shapes record the union of observed types; a command whose shape depends on the machine
  gets a stated exemption with a reason, listed in the map.
- **P5 The bundle cannot be signed before G6.** The owner key and `native-release` Environment do not exist yet
  (row 90 owner tasks). Guard: RG-S builds and tests against a throwaway key; the readiness row "bundles signed"
  stays red until the owner tasks land, which surfaces the dependency at G5 instead of at publication.
- **P6 Counsel answers late.** The license checkpoint holds the release. Guard: the checker separates
  day-to-day wording (green now) from the release-time licensor check, so engineering is not blocked; the
  readiness instance shows the one red row and who owns it.
- **P7 The Mac is busy or moved.** macOS arm64 smoke has no other host. Guard: the smoke is short (minutes);
  check the Mac's lock before starting; if the address changed, ask Cam (mac-mini-node skill).
- **P8 Orphan goldens hide a real determinism gap.** RG-F1 traces them; if the producer is gone they are
  recorded (FU-2), not deleted, and the map row for determinism names only tests that read their files.
- **P9 Engine patch releases after D-4 skip a check.** Guard: every patch goes through `cut-release.sh` and
  G2 onward rerun; the instance records each tag.
