## 1. Frame

### Problem (facts read from the code)

1. **The docs gate fails open on the combined site.** `W:docs-src/lib/docs/publish-gate.ts:14` hides `/docs` in a
   production build unless `DOCS_PUBLISHED=true`. But `W:scripts/build-docs.sh:21` sets
   `DOCS_PUBLISHED="${DOCS_PUBLISHED:-true}"`, so every `npm run check` and every deploy builds the tree open. The
   roadmap says "docs held draft"; the build does the opposite. Nothing is served today only because the Pages
   deploy fails (every run since 2026-10-25) and trydecoy.com serves a "Coming Soon" page from another host. When
   REL-WEB RW-H makes the deploy green, the whole docs tree goes live before launch.
2. **Two launch flags.** The site has `prelaunch: true` (`W:src/_data/site.json:6`), which REL-WEB flips after the
   1.0.0 smoke (REL-WEB section 4 step 4). The docs have their own env flag. D-5 ("Fumadocs launch-gate flip") and
   the `prelaunch` flip are one event but two facts that can disagree.
3. **`llms.txt` ignores the gate.** `W:docs-src/scripts/build-llms-txt.mjs` writes `public/llms.txt` with every
   non-draft page in `prebuild`, and `W:scripts/build-docs.sh:32` copies it to `dist/`. Page titles also go into
   each page's metadata (`W:docs-src/app/docs/[[...slug]]/page.tsx:35-41`).
4. **The install page is wrong for V1.** `W:docs-src/content/docs/start/install.mdx:14-37` tells users to clone two
   repos and `pip install -e`, says PyPI `decoy-cli` is the future path, and shows `decoy doctor` output with CLI
   `0.1.0` and engine `0.4.0`. V1 ships signed bundles (`C:docs/install.md:1-12`).
5. **The CLI reference is a month old.** The vendored `W:docs-src/content/docs/reference/cli/_source/cli-reference.md`
   names CLI commit `e61baed6` (decoy-web commit `61bf6cb`, 2026-10-24). About 300 CLI PRs merged since.
6. **No truth check reads the docs pages.** `W:scripts/check-claims.mjs:27-28` skips `dist/docs` and `docs.html`.
   `W:scripts/check-snippets.mjs` checks `decoy <command>` only in marketing snippets and `.njk` pages, never in
   docs code blocks.
7. **License text in the docs check is stale.** `W:docs-src/scripts/check-docs-truth.mjs:53,94-95,115` says
   BUSL-1.1 and "until the Apache-2.0 flip". The owner's license is FSL-1.1-ALv2 (2026-11-10).
8. **Two security contacts.** `C:SECURITY.md:7` names GitHub Private Vulnerability Reporting.
   `W:src/_data/site.json:11` names `security@trydecoy.com`. Readiness row 13 needs one "security contact".
9. **No release notes page.** `W:docs-src/content/docs/release/index.mdx` is `draft: true` with placeholder text.
10. **A platform page is not a draft.** `W:docs-src/content/docs/platform/index.mdx` ("Platform user guide") has no
    `draft: true`, while the platform is parked until after CLI V1.

### Guarantee (what REL-DOCS promises)

- G-1 One launch fact. `site.json` `prelaunch` alone decides whether the docs tree ships. While it is `true`,
  `dist/` holds no docs page, no docs asset, no search index and no `llms.txt`; `/docs/` serves one placeholder
  page. When it is `false`, the full tree ships.
- G-2 The install, upgrade, offline install, uninstall, release notes and security contact pages are generated from
  the CLI's own files at one recorded CLI commit. Nobody hand-copies them.
- G-3 At launch (`prelaunch: false`), the vendored CLI files name the same version as the published
  `src/cli/version.json` `latest` (REL-WEB), and every published hand-written page says it was checked against
  that version.
- G-4 Every `decoy <command>` in a docs code block exists in the vendored CLI reference, and the docs pages pass the
  same banned-claims list as the marketing pages.
- G-5 The site and the docs name the same security contact as `C:SECURITY.md`.

### Non-goals

- The download page, `/cli/` files, `/proof` and the version document (REL-WEB, row 91).
- Signing, publishing and the smoke from the published artifact (CLI-REL, row 94).
- `CLAIMS-AUDIT.md` (REL-WEB Q7: the orchestrator owns it) and the B-3 claims sign-off (REL-GATE readiness row 12).
- New docs pages beyond the release set above. The "Later" list in the docs build plan (A-Z workflow guide,
  in-browser demos) stays later.
- Platform (Studio) docs. They stay draft until the platform restarts.
- The engine's own README and `pip install` wording (REL-GATE RG-L owns it).
- Windows install docs (rows 6 and 89).

## 2. Established solutions

Searches run 2026-11-18 (web and the repos): "static site docs launch gate single flag", "vendor upstream markdown
into a docs site at a pinned ref", Fumadocs loader plugins and `.md` support, Next.js static export with `notFound`.

- Content flags: one build-time flag read by every consumer is the usual pattern (Eleventy global data, Next.js env
  at build). This plan follows it. `site.json` is Eleventy global data already, and the build script turns it into
  the env the Next app reads. No new flag store.
- Vendoring upstream docs: this repo already vendors the CLI reference with a provenance header and a pinned commit
  (`W:docs-src/scripts/sync-cli-reference.mjs:15-16`), and splits it into pages with a loud-fail parser
  (`build-cli-mdx.mjs`). Docusaurus and Fumadocs both describe the same "copy at a ref, generate pages in prebuild"
  approach for remote content. This plan widens the existing script; it adds no second sync tool.
- MDX safety: MDX parses `{` and `<` as JSX. Fumadocs also loads plain `.md` files (the `files` glob in
  `W:docs-src/source.config.ts` already includes `**/*.md`), which do not parse JSX. The generated pages are `.md`;
  the generator still refuses raw HTML blocks.
- Release notes from a Keep a Changelog file: tools such as `keepachangelog` split on `## [x.y.z]` headings. The
  split needed here is one heading pattern; a dependency is not worth it. The generator fails loud on an
  unknown heading shape.
- Security contact: RFC 9116 `security.txt` is the standard machine-readable contact. It is a new public surface, so
  it is owner question OQ-4, not part of the build.

## 3. Design notes

1. **One launch fact, one reader.** `W:scripts/lib/launch.mjs` (new, beside RW-K's `old-org.mjs` and RW-H's
   `contract.mjs`) exports `isPrelaunch()`. It reads `src/_data/site.json` and throws `launch_flag_invalid` unless
   `prelaunch` is a boolean. `build-docs.sh` and the new `check-docs-gate.mjs` call it; nothing else in the build
   reads `prelaunch` for the docs. `publish-gate.ts` stays the app's one gate; it keeps reading `DOCS_PUBLISHED`,
   which only `build-docs.sh` sets for the combined site. Every deployed file comes from `npm run check`, and only
   two steps in it can emit docs output: Eleventy (the placeholder and the links in marketing pages) and
   `build-docs.sh` (the export). Both read the one fact. The standalone `docs-src` export is not deployed by any
   workflow (`W:.github/workflows/deploy.yml` uploads `dist/` after `npm run check`), so this plan does not change
   it. The guard that proves no consumer bypasses the fact is output-based: `check-docs-gate.mjs` reads the final
   `dist/` in the deploy job, so any new step that copies docs output under prelaunch fails the deploy (M-G6).
2. **Hidden means absent.** While `prelaunch` is `true`, `build-docs.sh` removes any earlier docs output from
   `dist/` (every entry under `docs/` except `docs/index.html`, which is the placeholder Eleventy wrote just
   before, plus `_next/`, `api/`, `docs.html`, `llms.txt`), skips the Next build, and exits 0. Skipping the
   build is simpler and stronger than building a hidden tree and filtering it.
3. **Placeholder.** `W:src/docs-prelaunch.njk` (new) has `permalink: /docs/index.html` when `site.prelaunch` is
   true and `permalink: false` otherwise. Text: "The documentation publishes with the 1.0.0 release." and a link to
   `/cli/`. It uses the existing page layout. When `prelaunch` is false, `build-docs.sh` already runs
   `rm -rf dist/docs` before it copies the export, so the placeholder can never shadow the docs.
   Marketing pages and `site.json` link to deep docs pages (`W:src/_data/site.json:46-51` footer, `src/cli.njk`,
   `src/index.njk`, `src/how-it-works.njk`). An Eleventy transform in `eleventy.config.js` (one choke point, 52
   lines today) rewrites every `href="/docs/<anything>"` in emitted marketing HTML to `href="/docs/"` while
   `site.prelaunch` is true, so no marketing link points at an absent page. It does nothing when `prelaunch` is
   false. The existing `check-links.mjs dist` is the guard (AT-G3).
4. **Caller conflict.** A caller that sets `DOCS_PUBLISHED` to a value that disagrees with `site.json` gets exit 1
   `docs_gate_conflict` from `build-docs.sh`. A local preview of the hidden tree uses `pnpm dev` inside `docs-src/`,
   which `publish-gate.ts` already renders in full outside production.
5. **One vendored set.** `sync-cli-reference.mjs` gains a fixed list `VENDORED = ["docs/cli-reference.md",
   "docs/install.md", "CHANGELOG.md", "SECURITY.md"]` and writes all four, byte for byte, into the existing
   `docs-src/content/docs/reference/cli/_source/` folder (underscore folders are not pages: the `files` rule in
   `W:docs-src/source.config.ts`). It also writes `_source/source.json`: `{repo, commit, version, files: {name:
   sha256}}`, where `version` is `C:pyproject.toml` `[project] version` at that commit. The header comment on
   `cli-reference.md` stays as it is today. The script refuses a dirty CLI checkout (`git status --porcelain` not
   empty), so the commit names exactly the bytes copied.
6. **Generated pages.** `W:docs-src/scripts/build-vendored-pages.mjs` (new, beside `build-cli-mdx.mjs`, run in
   `prebuild` and `predev`) writes three gitignored pages, the same way the generated reference pages are ignored:
   - `content/docs/start/install.md` from `install.md`: drops the H1, keeps every section (quick install, supported
     platforms, what the installer verifies, upgrading, update notice, offline install, uninstall, where things
     live);
   - `content/docs/release/notes.md` from the newest `## [x.y.z]` section of `CHANGELOG.md`, or a page with
     `draft: true` when no released section exists (never `[Unreleased]`);
   - `content/docs/release/security.md` from the "Reporting a vulnerability" section of `SECURITY.md`.
   Each page gets fixed frontmatter (title, description) and a last line naming the CLI version and commit.
   Relative links resolve to `https://github.com/decoy-data/decoy/blob/<commit>/<path>`. The generator refuses raw
   HTML blocks and an unknown heading shape (exit 1, the file and line named). The hand-written
   `start/install.mdx` and the placeholder `release/index.mdx` are deleted; `release/meta.json` lists `notes` and
   `security`.
7. **Checks extend existing scripts.** `check-snippets.mjs` adds docs code blocks to its sources and keeps the
   vendored reference path. `check-claims.mjs` stops skipping `docs` and `docs.html`. `check-docs-truth.mjs`
   updates its license text and adds the install-path, platform-draft, security-contact and page-verified checks
   (section 5.3). No new checker framework.
8. **Page-verified field.** Hand-written pages carry `verified_cli: "<version>"` in frontmatter (the schema in
   `source.config.ts` gains it as an optional string). Under `prelaunch: true` the check prints counts only. Under
   `false`, a published hand page whose `verified_cli` differs from `source.json` `version` fails `page_unverified`.
   Generated pages are exempt because their bytes come from the vendored set.

## 4. Release sequence (release-and-rollback)

1. Before REL-GATE G3 (frozen heads): RDOC-G, RDOC-V and RDOC-C merge on decoy-web, and RDOC-L on the CLI. The site
   stays `prelaunch: true`; `dist/` carries only the placeholder under `/docs/`.
2. At G3: run `pnpm sync:cli-ref` against a clean CLI checkout at the release-candidate commit, then RDOC-P checks
   each hand page against that version and sets `verified_cli`.
3. At G7, readiness row 13: the evidence is the decoy-web commit of step 2 and the currency record.
4. At launch: the commit that flips `prelaunch` to `false` (REL-WEB section 4 step 4) also publishes the docs. If
   the CLI changed after step 2, re-sync first; `check-docs-gate.mjs` refuses with `docs_source_stale` otherwise.

Rollback: a bad docs page is a normal decoy-web revert and redeploy. To withdraw the whole tree after launch, set
`prelaunch` back to `true` and redeploy; the docs leave `dist/` with no other change. No step here is one-way.

Health signal after launch: `https://trydecoy.com/docs/start/install/` serves the generated page with the 1.0.0
version line, and `/llms.txt` lists the docs pages. The row 94 smoke step reads both.

## 5. Behavior

### 5.1 RDOC-G: the launch gate (decoy-web)

- `scripts/lib/launch.mjs`: `isPrelaunch(sitePath)` as in note 1, default path `src/_data/site.json` relative to
  the repo root; CLI mode `node scripts/lib/launch.mjs --docs-published` prints `true` or `false`. No env override:
  tests run the real scripts in a temporary copy of the repo (see section 8).
- `scripts/build-docs.sh`: line 21 becomes a call to `launch.mjs --docs-published`; a disagreeing caller value
  exits 1 with `docs_gate_conflict`. When `--docs-published` prints `false` (that is, `prelaunch` is `true`), the script removes earlier docs output and keeps
  only the placeholder (note 2), prints
  `docs withheld (prelaunch)` to stderr and exits 0 before `pnpm install`.
- `src/docs-prelaunch.njk`: the placeholder (note 3).
- `eleventy.config.js`: the docs-link transform (note 3).
- `scripts/check-docs-gate.mjs <dist> [--site <site.json>]` (new; `npm run check` runs it after `build:all` as
  `node scripts/check-docs-gate.mjs dist`, the same argument form as `check-links.mjs dist`): with `prelaunch: true`, `dist/` has
  exactly one file under `docs/` (`docs/index.html`, the placeholder), and no `_next/`, `api/`, `llms.txt` or
  `docs.html` (`docs_leak_prelaunch`). With `false`, `dist/docs/` holds at least `MIN_DOCS_PAGES = 60` HTML files
  and `llms.txt` exists (`docs_missing_at_launch`); the vendored-set checks in 5.2 also run.
- `docs-src/content/docs/platform/index.mdx` gets `draft: true` (the other two platform pages already have it).

### 5.2 RDOC-V: one vendored CLI set and generated pages (decoy-web)

- `sync-cli-reference.mjs` as in note 5. Exit 1 on a missing file, a dirty checkout, or an unreadable version.
- `build-vendored-pages.mjs` as in note 6.
- `check-docs-gate.mjs` checks the vendored set in both states: every file in `source.json.files` exists and its
  SHA-256 matches (`docs_source_digest`); `cli-reference.md`'s header commit equals `source.json.commit`
  (`docs_source_mixed`). With `prelaunch: false`, `source.json.version` equals `src/cli/version.json` `latest`
  (`docs_source_stale`). Until RW-H creates `src/cli/`, there is no `version.json`; under `prelaunch: true` that is
  a pass with a printed note, and under `false` REL-WEB's `dist_missing_at_launch` already fails the build.

### 5.3 RDOC-C: truth checks over the docs (decoy-web)

- `scripts/check-snippets.mjs`: sources add every fenced block tagged `bash`, `sh`, `shell` or `console` in
  `docs-src/content/docs/**/*.md` and `*.mdx`. Generated reference pages (`reference/cli/*.mdx`) are skipped,
  since they are the reference.
- `scripts/check-claims.mjs`: the walk no longer skips `docs` or `docs.html`; it still skips `_next`, `api`, `js`
  and `css`. The placeholder text avoids the banned "coming soon".
- `docs-src/scripts/check-docs-truth.mjs`:
  - check 2 text: "source-available under FSL-1.1-ALv2, not open source" (lines 53, 94-95, 115); the rule is
    unchanged;
  - check 6 `install-path`: a published page other than the generated install page may not contain
    `pip install decoy-cli`, `pip install -e`, or a `git clone` of `decoy` or `decoy-engine`;
  - check 7 `platform-draft`: every page under `platform/` has `draft: true`. The message names row 92 and the
    platform restart, so removing the check later is a deliberate edit;
  - check 8 `security-contact`: `W:src/_data/site.json` `contacts.security`, when set, appears in the vendored
    `SECURITY.md`;
  - check 9 `page-verified`: note 8.
- Pages that the new checks flag are fixed at the page in this slice (or moved to RDOC-P1 if the slice nears its
  line cap).

### 5.4 RDOC-P: currency pass at the release candidate (decoy-web, plus a CLI record)

Each published hand page (about 85: 89 `.mdx` files today, less drafts, partials and the deleted install page) is
read against the CLI at the vendored commit and the engine D-4 tag. Each command, flag, exit code, YAML key and
sample output is run on the Mac or a VM (never the devbox) or checked against the vendored reference. Wrong text is
fixed in place, and the page gets `verified_cli`. The record `C:docs/records/YYYY-MM-DD-docs-currency-1.0.0.md`
lists each page, its verdict (unchanged, fixed, drafted) and the decoy-web commit. A page that cannot be made true
for 1.0.0 is set `draft: true` and listed; it is not rewritten into a new feature description.

### 5.5 RDOC-L: CLI doc lines (CLI)

- `C:docs/roadmap/release-gates.md` D-5 line: the docs publish with the `prelaunch` flip on decoy-web (REL-DOCS).
- `C:docs/release/release-readiness.md` row 13 evidence adds the decoy-web commit of the RDOC-P sync and the
  currency record path.
- `C:docs/ROADMAP.md` row 92: plan link and state. No sentry or code change.

## 14. Pre-mortem

- RW-H's first green deploy ships before RDOC-G merges, and the docs go public early. Mitigation: RDOC-G is a
  hard predecessor of RW-H (section 13), and RW-H's gate checks that `scripts/check-docs-gate.mjs` is on main.
  The deploy has failed on every run since 2026-10-25, so no deploy can go green before RW-H.
- `C:docs/install.md` uses a construct the generator refuses (an HTML comment, a raw tag). Mitigation: AT-V3 fails
  loud with file and line; the fix goes into `install.md` (one source), not into a generator special case.
- The currency pass turns into a docs rewrite. Mitigation: 5.4 limits it to checking and fixing what is wrong, or
  drafting a page. New pages are out of scope.
- `MIN_DOCS_PAGES` is wrong after RDOC-P drafts pages. Mitigation: the floor (60) sits well below the 85 hand
  pages plus the generated reference pages. RDOC-P records the count; lowering the floor is a recorded owner
  decision, not a quiet edit.
- RW-H and RDOC-G both edit `build-docs.sh`. Mitigation: RW-H rebases on RDOC-G. RW-H removes only the last
  `_redirects` line; RDOC-G changes line 21 and adds the withheld branch.
- The CLI moves after the RC sync. Mitigation: `docs_source_stale` at launch forces a re-sync before the
  `prelaunch` flip.
